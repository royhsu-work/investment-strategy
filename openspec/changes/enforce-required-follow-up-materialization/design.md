## Decisions

### D1 — Source and completion

Use the existing qualified decision/accepted intent, exact source Issue/Change, decision reference and bounded scope. Record explicit required work, affected dependent Issues and applicable prerequisites under existing decision authority. No new business key. Unregistered intent discrepancies go to semantic review. Neither requested_effects omission nor READY/PASS overrides a still-applicable registered decision. Persist an Explore defer result before operations requiring its reference; withhold its successor until read-back. Other readiness and lifecycle consumers check the same postcondition. Keep optional, uncommitted work outside the queue.

### D2 — Reconcile the operation through existing Application

Read the complete, qualified relevant Issue population, including closed/advanced carriers, and independently verify source, scope, authority and intended state. Reuse an admissible open or positively qualified descendant. Repair only missing authorized fields on a freshly bound Issue, preserving unrelated state. A retired carrier with a still-applicable decision may require replacement after reauthorization. Contradiction, stale authority, malformed evidence or incomplete enumeration allows no write. With zero reusable/repairable carriers and full fresh authorization, perform one necessary create then reobserve; a later legal wake may repeat the observation and issue its own necessary create. An old delayed POST may also commit. Multiple individually qualified matches satisfy existence; they neither transfer gate evidence nor elect a permanent tracker. For a specific downstream edge require authority for its actual target; Lead/maintainer can correct ambiguity without excluding independent work.

Reuse admission pagination, routing predicates, exact mutation/read-back and the Application job's existing issues:write. Do not borrow idle NO_WORK or trust copied source markers. The physical prior attempt remains UNKNOWN. Other mutations retain their existing proof requirements, including CompleteNeverCalledWitness where applicable.

Today _application_continuation_body(None) emits no transport, and the ordinary wire requires an actual predecessor artifact. A create-guard change alone cannot fix F1. Extend the existing continuation producer AND consumer for this bounded operation. Carry the exact accepted-decision reference as the demonstrable basis when no predecessor artifact exists; prohibit fabricated artifact IDs. Reuse ordinary continuation when applicable. Discovery of the pending suffix cannot require the affected producer to win a new semantic dispatch. Preserve all independent blockers, including an explicit edge to the very same target. Verify the full graph first. Only the producer's own new hold is excluded from exact effect continuation; new semantic work remains suspended. ### D4 — One Issue DAG, conditional complete-set correction

Retain _declared_blockers, _read_dependencies, acquire_current_github_preflight and select_work as the shared projection. A source decision describes an outstanding required effect; the downstream Issue declaration remains the durable set of actual edges. Do not derive permanent edges from a source after correction. Completion requires current observed edges, qualified terminal release or authoritative supersession and all required read-backs. Ordinary Issue closure and NO_GO never count as successful prerequisite delivery.

The baseline latest-command rule loses independent edges even after the first writer has read back success. Append complete-set corrections referencing the native comment ID of the observed effective declaration (explicit empty initial basis when none). Fold qualified commands in existing native creation-time/ID order. Preserve the legacy prefix. First managed correction must match the last effective legacy basis. Once managed, every complete-set writer for that Issue, including withdrawal, must cite the effective basis. A late unbased or stale replacement cannot overwrite it. On conflict, reread and apply only the still-authorized disjoint edit to the new set. If its old edge no longer exists and the requested replacement is not already established, return to the existing semantic correction owner. Independent Issues need no global order. Edits, incomplete history, cycles and missing targets remain invalid. Include legacy and managed clients in cutover tests.

Direct owner/qualified Connector declarations retain existing provenance. Authorize a native Application-produced correction only against the exact accepted source, affected Issue, expected base, allowed additions/removals, projected graph and read-back. Bot identity alone grants nothing. A qualified maintainer can correct an affected downstream while the former prerequisite is still suspended. Replacing A with B never establishes B's completion; the existing completion qualifier evaluates B separately.

### D5 — Resume, retire, and preserve the remaining obligations

Use existing Explore fresh revalidation or the applicable formal material resume/correction boundary. Re-run original acceptance against current main; an unmerged branch provides no delivery proof. Preserve remaining scope for partial satisfaction and use independent review when approved meaning changes. Do not add a gate to every Action. Existing resolve-question/READY retains a PR close but returns to implementation, and normalization drops that close on NO_GO. Extend the existing bounded retirement plan and its normalization/recovery for the applicable terminal result. Verify exact carrier type, repository, head, unmerged status and specific retirement authority before and after close; never infer authority for another PR type. Complete or authoritatively supersede independent accepted effects, fulfill applicable branch cleanup or retention, then close/unroute with exact result attribution. A crash at any prefix resumes only the missing suffix. No fake replacement, merge, archive or lifecycle-complete. If a downstream still names the retired Issue it stays blocked until a qualified correction.
