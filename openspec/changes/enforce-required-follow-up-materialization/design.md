## Decisions

### D1 — Reuse the durable semantic source, not a worker effect list

Extend the existing accepted semantic-intent/result evidence contract at its current owner (worker parsing and qualified Application intent reconstruction). A source obligation is an explicitly classified bounded work identity, exact source Issue/Change/decision reference and revision, and the affected dependent Issue identities. Use a stable identity derived from the exact source decision plus its bounded follow-up identity, not mutable title text. Retain exact provenance and qualification, explicit optional/required distinction, and an exact authoritative supersession relationship where applicable. A later result or optional wording cannot erase a still-applicable independent required obligation.

Represent the structured decision in the existing durable qualified decision/result evidence, not a new Issue comment registry, database, lifecycle state or competing authority. Reconstruct the independently registered obligations from their qualified source(s) even when the current worker omits requested effects. The Application parses/qualifies exact evidence; it does not decide semantic scope from prose. A Human/Lead decision lacking machine registration remains a semantic discrepancy for independent review, not permission for the machine to invent an obligation or ignore the approved intent. Verify current authority and substantive Human freshness at consequential boundaries. Preserve supported historical source-linked tracker evidence and existing exact Explore RESULT reference semantics.

Consolidate the necessary tracker/dependency completion predicate into the existing Application consequence/effect contract (scheduled_agent_effect_contract.py: consequence_spec_for; scheduled_agent_effects.py and scheduled_agent_application_bridge.py). The normal path derives the authorized missing tracker operation from qualified source obligations, not an optional worker-requested effect. Existing review and readiness gates consume the same predicate and independently verify semantic correspondence. Do not make Reviewer a producer. Keep the existing Action Model transitions unchanged.

Reuse the source-linked candidate qualification, create/reuse and read-back mechanics where applicable from scheduled_agent_idle_admission.py, but not its NO_WORK _fresh_gate, correlation or idle authority. Normal required-follow-up materialization is an Application-owned effect derived from the accepted source. Use the existing repository-owned Application job with its existing issues:write permission; no Connector direct Issue creation by semantic workers and no native dependency mutation API. Exactly one qualified tracker may be adopted; create the action-only pre-activation tuple as one logical postcondition where the existing actuator supports it, or repair only missing authorized fields on the exact existing tracker. Retain source identity and existing unrelated labels/content. Qualified later descendant or terminal evidence of the same tracker is adopted, not rewound. Do not use a direct mutation to discover a target.

When Explore's exact ACTION_RESULT is the canonical defer reference, persist that source decision before its dependent materialization and do not confuse this source result with completed successor qualification. For other applicable READY/PASS/lifecycle boundaries, do not publish/qualify the final outcome or persist successor before the necessary source-derived postcondition. The existing accepted-intent and consequence owner reconstructs incomplete work; it does not run another semantic Action to recreate evidence.

## Risks / Trade-offs

- Unknown response to non-idempotent Issue creation: safety and liveness must be demonstrated with qualified evidence, not assumed; return genuine unresolved authority/capability conflict to Lead/Human.
- Historical routing/provenance: preserve exact accepted decisions and valid descendants; no retroactive rewriting or new role labels.
- Partial materialization and concurrent independent dependencies: derived source union avoids overwriting a sibling contribution, while full graph and current source qualification retain safety.
- Semantic omission vs deterministic omission: distinguish unregistered prose (independent semantic Review responsibility) from independently registered obligations (machine completeness responsibility). Do not strengthen the LLM prompt as a substitute for a machine-observable contract.
