# Design: Exact dispatch Artifact read and recovery at existing owners

## Decision boundary and evidence discipline

Source: Human #435, same-Issue accepted `Explore / PROPOSAL_READY` (#435 comments `6760518797`, `6760519420`), current-main governance/specs, original run/artifact metadata and existing reader source. The observed production failure is `_fresh_gate` returning `idle-dispatch-artifact-content-unavailable` with no mutation after run/Artifact metadata qualification. The `artifact_result()` catch masks the original exception. Connector extraction of raw 199-byte JSON and successful canonical parse prove those bytes under the connector surface only. They do **not** prove whether the native runner GET returned 200, 302, another status or other bytes. No repair branch may treat an unobserved HTTP/host/format hypothesis as historical fact.

Reconciliation reuses current GitHub state rather than remembering attempts.

## Failure taxonomy (not a routing state machine)

| Condition | Classification | Consequence |
| --- | --- | --- |
| Native GET 500/502/503/504, connection timeout | `READ_UNAVAILABLE` / transient | Bounded GET-only retry, then diagnostic fail-closed; later fresh wake may requalify. |
| Body unavailable/partial pagination/run not finished and recoverable | `RECOVERABLE_INCOMPLETE` | No write; explicit source/stage and fresh reobservation. |
| Signed redirect host/scheme not permitted | `REDIRECT_UNTRUSTED` | No signed-URL disclosure, token forwarding, write or permissive fallback. |
| Unexpected raw type, ZIP rather than canonical JSON, invalid UTF-8/JSON/schema | `PAYLOAD_FORMAT_INVALID` | No alternate parser; fail closed. |
| Declared size/digest and raw bytes differ | `INTEGRITY_MISMATCH` | Fail closed; no trust in connector metadata or content. |
| Wrong request/run/attempt/main revision or contradicted durable identity | `IDENTITY_STALE` | Fail closed; a different fresh legitimate dispatch is required. |
| Missing/duplicate/expired Artifact, structurally permanently illegal metadata/status | `PERMANENT_INVALID` | Fail closed with exact stage, never silently convert to transient. |

These categories attach to the **existing** result/error path and retain `mutation_attempted=false` for pre-write failures. 401/403/404 are observed HTTP statuses retained distinctly from 5xx, rather than guessed permission failures. Only safe status/operation/correlation fields may be logged; never bearer token, raw signed URL, private response text or secret-bearing headers. Unknown remains unknown.

## Contract oracle, Guard FMEA and typed boundaries

The **single normative guard/decision table** is in `specs/scheduled-agent-workflow/spec.md` under this Change. The existing reader and idle Application remain its only executors; tests project each table row into one rejected/uncertain witness and one adjacent lawful-positive witness. Do **not** reimplement the table as a second dispatch engine or replace long predicates with an opaque `is_safe(...)` wrapper. The existing flow is a series of small typed facts: **source-run identity → complete unique Artifact → safe byte transport → size/digest integrity → canonical disposition → fresh normal-dispatch/Issue eligibility → idempotent Application effect/postcondition**. A failed stage carries observed category and correlation forward; later stages cannot promote unknown evidence to success.

Guard FMEA is specified in the normative table, not duplicated in prose as a second truth source: identity guards prevent foreign/stale admission; Artifact completeness/digest guards prevent incomplete or forged bytes; redirect guard prevents credential disclosure; parser/disposition guard prevents arbitrary/malformed work selection; GET classification guard prevents false success and unbounded retries; fresh-eligibility guard prevents overriding active WIP; post-write reconciliation guard prevents duplicate issue/effect. **Every guard** needs an adjacent valid input and a terminal or later-fresh-wake continuation test. Recoverable read failure is not terminal BLOCKED forever; contradiction remains fail-closed until truly new authoritative evidence.

Use **Design by Contract** for preconditions/postconditions/invariants; **table-driven tests** use the normative rows as acceptance oracles; **Metamorphic Testing** presents equivalent digest-matched bytes through native direct 200, trusted signed 302 and a connector representation, expecting the same canonical normalized disposition and eligibility (without equating unsupported media claims). **Model-Based / Property-Based Stateful Fault Injection** generates bounded sequences of runner success/invalidity, transient GET faults/recovery, fresh/stale decisions, pre/post-write interruption, and one/two overlapping admissions across distinct wakes. Assert safety on every prefix and *conditional* eventual progress when a lawful later wake and authoritative reads exist. Fixed seeds plus shrunk/minimal counterexamples keep tests reproducible; no new state machine in production and no new property-testing dependency unless independently justified.

## Lawful executable native runner diagnostic (break the WIP circle)

The normal idle-admission workflow cannot produce genuine `NO_WORK` while #435 is the active WIP. Consequently, task 1.2 **MUST NOT** depend on clearing #435 or a direct manual workflow execution. The existing same-repository `.github/workflows/quality.yml` has an ordinary `pull_request` trigger on `src/**`, `tests/**`, and that workflow path. An Executor may add the *smallest possible temporary, read-only, automatically PR-triggered diagnostic step/test* to that existing job, conditional on native CI permissions. It must target a fresh-verified already successful exact run/attempt/Artifact, request only read permission (for example `actions: read` if applicable), and log redacted response stage/status/redirect host class/byte count/hash or sanitized exception, plus run/attempt/artifact/request correlation. Never directly dispatch/run Actions, create an Issue, relabel, write a branch as a probe, or expose any token/redirect URL. Normal implementation PR commits that are independently necessary can trigger the existing quality workflow; the diagnosis step is scoped and removed or locked down after use.

That **quality job is a legal runner-origin observation**, but not automatically the failing idle-admission runner environment. Before inferring the historical failure cause, verify equivalent repository installation/token authorization, API host, reader code/headers, permission scope and relevant redirect/response behavior against the production `Scheduled Agent Application` idle job (`actions: read, contents: read, issues: write` in its current workflow). A separate read-only quality job with `actions: read` may have different capabilities; differences are a finding, not a confirmed root cause. If CI cannot grant a diagnostically equivalent read, record the unresolved stage as **UNKNOWN**. The ordinary staged path is then: RED contract tests → deploy bounded generic stage instrumentation (no transport-specific behavior guess) → observe next lawful native run under its existing owner → select smallest supported transport fix. This staged path does not discharge the mandatory production diagnosis/repair/acceptance outcome; it simply avoids circular dependence on idle NO_WORK while WIP exists.

## Diagnostic-first decision procedure

1. RED: replay the original normalized 199-byte NO_WORK bytes and metadata; inject the native runner-side URL opener's actual 200 JSON, 302 trusted signed URL, status errors, truncated reads, incorrect bytes, host and authentication behavior. Verify each currently collapses or lacks sufficient integrity/stage information, proving a target-behavior RED, not a fixture/import failure.
2. Capture a **real**, lawful GitHub Actions runner-origin read-only observation with the existing automatically PR-triggered `Python Quality` entrypoint described above, or stage generic diagnostic instrumentation through the existing idle owner if the CI permissions/environment cannot reproduce the original read. Correlate exact request/run/attempt/Artifact/size/digest and sanitized status/host class/byte count/hash. Compare the credential/host/headers/reader contracts before labeling the observation equivalent to the failing idle job. The immutable fixture digest is suitable for repeatable tests; transient signed URLs/tokens are not artifacts. No direct-run Actions, repository mutation as a probe, guessed exception or transport-specific fix without attributable evidence. If runner equivalence is not established, record `UNKNOWN` even if the surrogate quality job succeeds.
3. GREEN: implement shared safe bytes path only for the observed failure and all approved general contract cases. The exact correction remains inside current read/idle owners, and the case-specific hypothesis is tested against the full matrix before selection. If an observation reveals an incompatible upstream media contract, adapt the existing reader/decoder once and make producer/parser/validator agree; a material change to an approved schema/outcome returns to Lead/Human as governance requires.
4. REFACTOR: remove the characterized duplicate transport path; keep security/no-bearer-forwarding and canonical parsing; run targeted and entire regression, lint/type and exact-head validation.

## Validation matrix

- **Positive:** exact request → successful run/attempt → unique unexpired Artifact; native direct HTTP 200 raw JSON; 302 trusted signed HTTPS redirect; canonical NO_WORK and authoritative digest/size. Existing AUTHORIZE and FAIL_CLOSED must never enter idle mode.
- **Correlation:** wrong comment, run id/title/path/event/conclusion/attempt, revision, Artifact id, duplicate/missing/expired/list-total mismatch, wrong disposition/schema; size, SHA-256, UTF-8 and partial content.
- **Fault injection:** 401/403/404, 500/502/503/504 (within and beyond GET bound), timeout, untrusted redirect, 302 without Location, signed read failing, JSON/ZIP representation mismatch, truncated/empty body, malformed JSON, digest mismatch, incomplete pagination.
- **Contract / Guard FMEA:** each canonical spec decision-table row has its actual source/precondition, blocked concrete harm, fail-closed/recovery outcome and adjacent lawful-positive twin, with one shared producer/parser representation.
- **Metamorphic:** equivalent exact canonical bytes and identity over supported native direct 200, trusted 302 and connector presentations normalize to the same accepted/nonaccepted decision; unsupported representation never gains authority.
- **Generated state model:** bounded/reproducible property-based sequences span success/failure/repair, stale/fresh authority, overlapping admissions, interruption and separate wakes; safety for each prefix and conditional completion only under lawful recovered inputs.
- **Stateful:** one/two overlapping attempts; interruption pre-read, pre-write, and unknown post-write; stale/replay/no-rewind; original Issue body and unrelated labels unchanged; fresh reauthorization suppresses mutation when new formal work appears; recoverable read requalifies on a fresh wake.
- **Negative authority:** never retry POST/PATCH, never use writes as probes, no new Issue/Action/queue/lease/registry, no substitution of old shard/Artifact, no manual routing, no token leak.
