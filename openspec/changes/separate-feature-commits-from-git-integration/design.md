## Decisions
1. **REUSE** existing Application identity, authority, materialization proof, manifest, tree/commit construction and mutation carrier. **CONSOLIDATE** feature-local writes onto one actual feature parent P. A/B/P/D remain separate; A immutable accepted authorization, B declared graph anchor, P actual feature preimage, D current default governance and integration base. Check every expected_sha at P and exact tree delta. Keep first-carrier path absence and identity. Conditional non-force publication verifies expected ref and postconditions. No blanket default-path veto for this operation.
2. **REMOVE** path-intersection-as-conflict shortcut from feature writes and native clean merge qualification. **REUSE** Git common ancestor and three-way merge engine. Keep actual content conflicts separate from stale/unknown observation. Resolution is an Executor-owned bounded operation with exact parent identities, reviewed tree, non-force conditional publication; independent review of the resulting feature head; no second positive proof owner. Retain all unaffected file content. For a clean integration candidate, use qualified native Git result; do not construct a parallel path-based merge algorithm.
3. **REUSE/CONSOLIDATE** canonical materialization proof for recovery: immutable witness W and current target T, exact identity, content at W, complete lineage to T, non-conflict at the operation in question. A later valid merge or resolution may alter accepted paths while preserving W. Do not replay a proven commit, treat historical missing evidence as absence, or equate separate forward correction with original physical effect. Keep old-plan safety and accepted-intent boundaries. The first-carrier identity and path-absence rules remain strict.
4. **ADD** an exact integration-candidate mechanical check within existing quality/validation and merge-acceptance ownership, because feature-head CI cannot prove combined-tree correctness. Verify actual base/head, native candidate commit and parents/tree, checkout, required quality and pinned strict OpenSpec validation. Consume the current candidate, not an old green run or synthetic revision without checkout proof. Reobserve current base/head just before merge and exact actual merged tree afterwards. Use the existing exact-head merge protection and normal correction/reconciliation path for concurrent base movement; do not claim completion without observed current consequence and applicable gates. Feature review is independently exact-HEAD; integration mechanical checks do not replace it. No permanent synchronization, global serial queue, duplicate semantic review gate, or new persistent status.
5. **NO-DELTA** dispatcher, dependency/WIP, action vocabulary, Human authority, archive/terminal ownership and T1 outcome. No Skill change planned; existing role/procedure reused. No independent maintenance candidate is itself an approval. The existing #467 code/test delta is a reusable input; compare against then-current main, preserve #469, reconcile candidate implementation only under formal Executor authorization. Current initial materialization permits only new Change artifacts under canonical agent branch, so formal specification carrier is distinct from the existing maintenance candidate; do not merge both or duplicate implementation work. Retain #467 as evidence until its work is accounted for; no unapproved deletion or closure.

Slice 1 covers feature-local publication and safe proof of existing work; slice 2 native integration and resolution with recovery; slice 3 distinct integrated checks and current merge eligibility. Each is executable and verifiable in the carrier with RED/GREEN/refactor, full tests, type/lint, strict spec; do not release an incomplete contract to main if the current N-1 cannot safely satisfy the complete approved stage.
